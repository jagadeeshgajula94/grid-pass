# GridPass security policy

## Supported versions

GridPass has no supported application releases yet. Maintainers should document supported versions and security update coverage here before the first release.

## Reporting a vulnerability

Use **Security → Report a vulnerability** in the GitHub repository if private vulnerability reporting is enabled. If it is unavailable, ask a maintainer for a private reporting channel without describing the vulnerability publicly. Do not open a public issue or PR with vulnerability details, credentials, or personal data.

Include the affected component and version or commit, impact, the conditions needed to observe the issue, and any redacted evidence that helps investigate it. Do not access anyone else's data or disrupt services while investigating.

## Triage and disclosure

Maintainers should acknowledge reports privately, assess impact and affected versions, agree on next steps and coordinated disclosure with the reporter, and publish an advisory when appropriate. Maintainers should document the private reporting channel, ownership, and response targets before the first release.

For engineering requirements, see the [security rules](.devin/rules/security.md). For design risks and mitigations, see the [architecture and threat-model template](docs/ARCHITECTURE.md).
